## Phase Goal

**As a** trader, **I want to** get clean errors and consistent chat actions, **so that** the AI copilot is reliable.

This gap-closure plan fixes the one defect the verifier found (gap G-02-1, review finding CR-01): a model reply with a non-finite trade quantity turns a chat turn into an HTTP 500 after the turn is already stored.

<objective>
Reject non-finite trade quantities (NaN, Infinity, -Infinity, 1e999, and the string forms "inf", "nan", "-inf") at the `ChatReply` schema boundary. A reply carrying one then becomes a 502 `BAD_REPLY_ERROR` before anything runs or is stored (HARD-01, HARD-05). Prove it with a route-level regression test written first, guard the finite boundary, and finish with the full-suite gate (INT-04).

Purpose: today `TradeInstruction.quantity` is a plain `float`. Pydantic accepts non-finite values, the trade fails as an action carrying `inf` or `nan`, `json.dumps` stores the turn, and FastAPI's response serializer (`allow_nan=False`) then raises. The result is a 500 with 2 chat rows committed. This breaks ROADMAP Phase 2 success criterion 1 ("never a 500") and criterion 3 (a failed action is delivered and the turn completes).
Output: a one-line schema change, 9 new test cases, and a green full suite (145 passed).
</objective>

## Assumptions

- Decision: a non-finite quantity rejects the entire reply (502, nothing runs). It does not fail only that one trade. This follows the verifier's prescribed fix and HARD-01: a reply with a number that is not valid JSON is unusable model output. The alternative was to keep the reply and fail only the trade with a sanitized quantity. That needs a second code path to clean the stored and returned actions, and it would still accept invalid JSON. The decision is reversible: one line in `schemas.py`.
- No `execute_trade` guard is added. It was listed as optional, and the planning-time probe showed all 8 non-finite REST combinations already return 400 (no 500 path).
- `1e999` is valid JSON syntax, but Python parses it to `inf`, so it is treated as non-finite.
- Very large finite quantities are not capped by the schema. They fail as actions through the insufficient cash or shares checks. A quantity cap is out of scope.
- `parse_reply` already logs the pydantic detail (including `input_value=nan`) at warning level. That is server-side only and was in place before this plan.
- Advisory items WR-02 and WR-03, and info items IN-01 and IN-02, are not part of this plan and stay open in `02-REVIEW-DISPOSITION.md`.
