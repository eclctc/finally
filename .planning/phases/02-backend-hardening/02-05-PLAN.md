## Phase Goal

**As a** trader, **I want to** get clean errors and consistent chat actions, **so that** the AI copilot is reliable.

This plan bounds what one AI reply can do to the portfolio, then closes the phase with the full-suite gate.

<objective>
Cap each chat turn at 5 trades and 5 watchlist changes, enforced in the chat service (HARD-06). Items over the cap are recorded as `failed` actions with a reason, and the reply is still accepted. Tell the model the cap in the system prompt. Then run the INT-04 gate: the full backend suite passes with a new test for every Phase 2 fix.

Purpose: an LLM reply (possibly prompt-injected) can list any number of orders today. The roadmap requires a service-level cap, not a schema constraint: `maxItems` on `ChatReply` would reject the whole reply with a 502 and change the `response_format` schema sent to the provider.
Output: `MAX_ACTIONS_PER_KIND`, `skipped()`, per-kind slicing, the prompt line, their tests, and a green full suite.
</objective>
