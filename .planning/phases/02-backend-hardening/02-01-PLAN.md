## Phase Goal

**As a** trader, **I want to** get clean errors and consistent chat actions, **so that** the AI copilot is reliable.

This plan delivers the "clean errors" half at the LLM boundary: every LLM failure mode reaches the client as a 502 with a fixed public message, never a 500 and never upstream text.

<objective>
Harden `backend/app/chat/llm.py` so every LLM failure mode (upstream exception, no choices, unusable content, timeout) raises `LLMError` built from a fixed module constant, logs the real cause server-side, and reaches the client as HTTP 502 through the existing router. The missing-API-key message stays as is.

Purpose: HARD-01, HARD-02 and HARD-03. Today `response.choices[0]` sits outside the `try` (500 on empty choices), the upstream exception text and the pydantic error (which echoes the model output) are returned to the client, and there is no request timeout (LiteLLM's default is 600 s).
Output: updated `llm.py`; new and updated tests in `tests/chat/test_llm.py` and `tests/chat/test_router.py`.
</objective>

## Assumptions

- A1 (research): 30 s is the LLM timeout. Easy to tune via TIMEOUT_SECONDS.
- A2 (research): the public message wordings above are acceptable; Phase 5 shows them verbatim.
- A3 (research): LiteLLM and OpenRouter exception text does not contain the API key. The log calls pass only fixed messages plus the exception, never request kwargs or headers.
- Decision: a response with no usable choice is reported with UPSTREAM_ERROR (the provider gave nothing back), while bad content is BAD_REPLY_ERROR. Both are 502.
