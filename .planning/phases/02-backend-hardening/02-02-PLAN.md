## Phase Goal

**As a** trader, **I want to** get clean errors and consistent chat actions, **so that** the AI copilot is reliable.

This plan makes the storage layer behave under load: duplicate watchlist adds never surface as a 500, and the history and chat queries stay fast as rows accumulate.

<objective>
Make the watchlist insert idempotent at the database (HARD-04) and add per-user, time-ordered indexes for the snapshot and chat queries (HARD-08). Both fixes land test-first.

Purpose: today two concurrent adds of the same ticker raise `sqlite3.IntegrityError` (reproduced in research: `['ZZZZ', IntegrityError('UNIQUE constraint failed: watchlist.user_id, watchlist.ticker')]`), which becomes a 500. The snapshot and chat queries scan their tables and sort in a TEMP B-TREE.
Output: `ON CONFLICT DO NOTHING` insert, two `CREATE INDEX IF NOT EXISTS` statements, and their tests.
</objective>
