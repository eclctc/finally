## Layout Contract

### Decision: the 1024px squeeze is fixed by raising the minimum width to 1280px and re-budgeting the columns (D-01)

Cause (01-UI-REVIEW.md): fixed columns 340 (watchlist) + 360 (chat) + 260 (trade) leave almost nothing at 1024px for the two `1fr` cells. Raising the width alone is not enough: with the old columns, 1280px still leaves about 158px per cell. The watchlist row needs 312px (budget above), so the watchlist is NOT narrowed below 320. The columns that give back width are chat (360 to 320) and trade (260 to 224).

Final values (these replace the Phase 1 "Layout Contract" numbers):

| Region | Old (Phase 1) | New (Phase 3) | Tailwind |
|--------|---------------|---------------|----------|
| Minimum page width | 1024px | 1280px | root `min-w-[1280px]` |
| Main grid (watchlist + center) | `minmax(300px,340px) 1fr` | `320px 1fr` | `grid-cols-[320px_minmax(0,1fr)]`, add `min-w-0` to `main` |
| Center grid columns | `1fr 1fr 260px` | `1fr 1fr 224px` | `grid-cols-[minmax(0,1fr)_minmax(0,1fr)_224px]` |
| Center grid rows | `1.25fr / 1fr / 0.85fr` | unchanged | `grid-rows-[minmax(0,1.25fr)_minmax(0,1fr)_minmax(0,0.85fr)]` |
| Chat column | `w-[360px]` | `w-[320px]` | `aside` `w-[320px] shrink-0` |

`minmax(0,1fr)` on the fluid tracks is required so Recharts content can never push a track wider than its share.

Arithmetic at the new minimum (1280px wide; `gap-px` gutters are 1px):

| Quantity | Width |
|----------|-------|
| Main region (page minus chat 320 minus 1px gutter) | 959px |
| Center region (main minus watchlist 320 minus 1px gutter) | 638px |
| Heatmap cell and the second fluid column (center minus trade 224 minus 2px gutters, halved) | 206px each |
| Chart cell and P&L cell (span 2 fluid columns plus the 1px gutter) | 413px |
| Positions cell (span 3) | 638px |

Every panel cell is at least 206px wide at the 1280px minimum. At the 1600x1000 E2E viewport: main 1279, center 958, fluid columns 366 each, Chart and P&L 733, rows about 366 / 293 / 249px (unchanged vertical behavior).

Vertical minimum: no new constraint. At a 1280x720 viewport the area under the 56px header is 664px and the rows resolve to about 268 / 214 / 182px. Each panel owns its own scroll, so a short window scrolls inside panels rather than the page.

Below 1280px wide the page scrolls horizontally (the same rule as before, now at 1280). This is the desktop-first trade-off recorded in PLAN.md.

## Watchlist Panel Contract

The `Watchlist` panel (`data-testid="watchlist"`, the existing Panel wrapper) contains, top to bottom:

1. Add form (always rendered, never scrolls away).
2. List region (loading, error, empty or rows).

The panel body already scrolls (`overflow-y-auto`). To keep the form pinned, the Watchlist content is a column: `flex h-full min-h-0 flex-col`, form `shrink-0`, list region `min-h-0 flex-1 overflow-y-auto`.

### Add form

- Container: `form`, `flex shrink-0 gap-2 border-b border-line p-2`. Height 45px (8 + 28 + 8 + 1px border).
- Input (`data-testid={testIds.watchlistAddInput}`): `min-w-0 flex-1`, 28px high, `bg-surface`, `border border-line`, `px-2`, Body, placeholder `Ticker` in `text-muted`. Focus border `border-primary`, no glow. Attributes: `autoComplete="off"`, `autoCapitalize="characters"`, `spellCheck={false}`, `aria-label="Ticker to add"`. Do NOT set `maxLength` (it would stop the user from ever triggering the inline 400 required by LIVE-06).
- Uppercasing: `onChange` stores `event.target.value.toUpperCase()` in state so the posted body and the visible text are uppercase. Submit trims whitespace and posts `{"ticker": value}`.
- Button (`data-testid={testIds.watchlistAddButton}`, `type="submit"`): 28px high, `bg-submit`, white Body at 600, `px-4`, label `Add`, hover `brightness-110`.
  - Disabled (`opacity-50 cursor-not-allowed`) while the request is pending or the trimmed input is empty.
  - Enter in the input submits through the form. A submit while pending is ignored.
- Success: clear the input, clear any error, refetch the list, scroll the added ticker's row into view, keep focus in the input. Adding an already watched ticker is a backend no-op success and behaves the same.
- Failure: keep the input text, show the error (below), keep focus in the input.
- Error line: directly below the form, `px-2 pb-2 text-down break-words`, `role="alert"`, id referenced by the input's `aria-describedby`. While it shows, the input has `border-down` and `aria-invalid="true"`. It clears on the next keystroke or the next submit. Absent from the DOM when there is no error.
- All strings render as React text nodes. Never `dangerouslySetInnerHTML` (the 400 echoes user input).

### Row anatomy (`data-testid={testIds.watchlistRow(ticker)}`, 28px)

```
| AAPL            214.61   +12.96%   [~~~~sparkline~~~~]   × |
  ticker (600)    price    change    64x20                 remove
  flex-1 truncate  72 min   64 right   fixed                24
```

Row: `li` inside a `ul` with an accessible name (`aria-label="Watchlist tickers"`), `flex h-7 items-center gap-1 px-2`. Row order is the order returned by `GET /api/watchlist` (the order the tickers were added). Row membership comes only from the REST list, never from the SSE keys.

Phase 3 rows are NOT interactive: no hover fill, no `tabIndex`, no pointer cursor, no selected style. Phase 4 adds selection (hover `bg-surface/60`, `tabIndex=0`, Enter/Space, accent ticker for the selected row). No other element inside the `watchlist` panel may use a testid starting with `watchlist-row-` (fresh-start.spec counts that prefix and expects exactly 10).

| Cell | Spec |
|------|------|
| Ticker | Body 600, `text-text`, `min-w-0 flex-1 truncate`. Tickers are 1 to 5 uppercase letters, so truncation is a safety net only. |
| Price | `data-testid={testIds.watchlistPrice(ticker)}`, `figures`, Body 400, `min-w-[72px] shrink-0 whitespace-nowrap px-1 text-right text-text`. `formatPrice` output only (`1,234.57`, no `$`). `--` when the store has no price. This element carries the flash (below). |
| Daily change | `figures`, Body, `w-16 shrink-0 whitespace-nowrap text-right`, `title="Change vs session open"`. Value is `(price - open_price) / open_price` through `formatPercent` (`+1.23%`). Color: `text-up` above zero, `text-down` below zero, `text-muted` at exactly zero or when showing `--`. Never use the frame's `change_percent` (it is per tick). |
| Sparkline | 64 x 20, `shrink-0`, wrapper `aria-hidden="true"` with `title="Since page load"`. Spec below. |
| Remove | `size-6 shrink-0` button, `×` glyph, `text-muted hover:text-down`, `aria-label="Remove {TICKER}"`, `data-testid={testIds.watchlistRemove(ticker)}`, `focus-visible:outline-2 outline-primary`, disabled with `opacity-50` while its DELETE is in flight. |

Remove behavior: `DELETE /api/watchlist/{encodeURIComponent(ticker)}`, then always refetch the list so the UI converges (including on 404). On success, clear that ticker's price entry and history from the store (a later re-add must not draw a line across the gap) and move focus to the add input (the removed button no longer exists, so focus would otherwise fall to the document body).

### Price flash (LIVE-04)

Inherits Phase 1 "Price flash" and adds the mechanics:

- The flash is on the `watchlist-price-T` element. Direction is computed in the price store by comparing the new price with the held price: higher is `up`, lower is `down`; equal, first value and repeated frame produce no flash. Never use the frame's `direction` (it is resent sticky for every ticker).
- While flashing: `bg-up/25` or `bg-down/25` with `transition-none`. After a hold of 50ms (`FLASH_HOLD_MS`) switch to `bg-transparent transition-colors duration-500 ease-out`, so the highlight fades over about 500ms. A hold of 0 paints nothing; do not remove it.
- Expose the state as `data-flash="up" | "down"` while flashing (absent otherwise) so tests assert on the attribute instead of Tailwind class strings. Use full literal class strings in a lookup map (Tailwind cannot detect `bg-${dir}/25`).
- Text color does not change during a flash. The header figures (`total-value`, `cash-balance`) never flash; the focal figure stays calm.
- `prefers-reduced-motion: reduce`: no flash at all (`motion-reduce:bg-transparent motion-reduce:transition-none`). Direction is still conveyed by the daily change color and the sparkline stroke. See Deviation #5.

### Sparkline (LIVE-05)

- Recharts `LineChart` with numeric `width={64} height={20}`, `data` = the ticker's capped price history, `accessibilityLayer={false}` (Recharts 3 adds a keyboard focus stop per chart otherwise), `margin` zero.
- `YAxis` hidden with `domain={["dataMin", "dataMax"]}`; no `XAxis`, grid, tooltip, legend or dots. `Line`: `dataKey="price"`, `dot={false}`, `isAnimationActive={false}`, `strokeWidth={1.5}`.
- Stroke by net direction since page load: `var(--color-up)` when the last point is above the first, `var(--color-down)` when below, `var(--color-muted)` when equal. Never a raw hex.
- Fewer than 2 points: render the same 64 x 20 empty box with no line.
- History is capped at 300 points per ticker and fills from the SSE stream, one point per new tick. It starts empty on page load, so lines fill in progressively.

## Header Contract (Phase 3 changes)

Layout, sizes, type and the `--` loading and failed states are unchanged from Phase 1. Changes:

### Wordmark is the page `h1` (D-04)

The wordmark `span` becomes `<h1 className="text-lg font-semibold leading-tight text-text">` with the same children (`Fin` + `<span className="text-accent">Ally</span>`). Panel titles remain `h2`, so the document has a single `h1` and a valid heading order.

### Connection dot (LIVE-02, D-03)

- Element: the same `connection-status` testid element, now `<span role="status" data-testid={testIds.connectionStatus} data-status={status} title={label} className="relative size-2.5 shrink-0 rounded-full {color}"><span className="sr-only">{label}</span></span>`. Remove the `aria-label` (the visually hidden text is the accessible name and the live announcement). `relative` keeps the `sr-only` child from affecting layout.
- Mapping:

| `data-status` | Class | Text / `title` | Meaning |
|---------------|-------|----------------|---------|
| `connected` | `bg-up` | `Connected` | `EventSource` OPEN (set on the `open` event, not on the first message) |
| `reconnecting` | `bg-accent` | `Reconnecting` | `EventSource` CONNECTING: before the first `open`, and during automatic retries |
| `disconnected` | `bg-down` | `Disconnected` | `EventSource` CLOSED (non-200 or non-`text/event-stream` response) |

- Initial state, before the first `open` event: `reconnecting` (yellow). It is the true state of the browser stream (CONNECTING) and avoids a red flash on every load.
- After a CLOSED error the stream is recreated after a fixed 1 second delay. The dot stays `disconnected` (red) until the recreated stream fires `open`, then turns `connected`. It does not flip to yellow while a recreated stream is retrying (avoids a 1 Hz red/yellow flicker when the server keeps answering non-200).
- Network-level drops (connection refused, reset, clean end-of-stream) leave the dot `reconnecting` while the browser retries on its own.
- Color is never the only signal: `title` and the hidden text carry the state name. The dot is not focusable and has no visible text.

### Live figures (LIVE-08)

- `total-value`: `formatCurrency` of `cash + sum(quantity x live store price)`, using the position's API `current_price` when the store has no price for that ticker. With no positions it equals cash (`$10,000.00` on a fresh DB). It updates in place with each price change, with no flash, no animation and no `aria-live` (a 2 Hz live region would flood screen readers). Width is stable because `.figures` is tabular and `whitespace-nowrap`.
- `cash-balance`: `formatCurrency` of the API `cash_balance`. It does not change in Phase 3 (trades arrive in Phase 4).
- Both show `--` until `/api/portfolio` answers, and keep `--` with the existing failed-state alert when it fails (unchanged). If the stream is down, `total-value` holds its last value; the dot is the staleness signal.

## Global

- `color-scheme: dark` on `html` (D-05). In `frontend/src/app/globals.css` add `html { color-scheme: dark; }` (or add the property to the existing `html, body` rule). This phase is the first to render a text input and a scrollable list, which is the trigger Phase 1 set. Effect: native scrollbars, input chrome and autofill match the dark theme.
- Keyboard focus ring for every interactive element (input, Add, each `×`): `focus-visible:outline-2 outline-primary` (inherited).
- Stream and store: one `EventSource` at the relative URL `/api/stream/prices`, owned by one module-level store with per-ticker subscriptions. Visual consequence: only rows whose ticker appears in a changed frame re-render, so a frame carrying only some tickers leaves the other rows untouched.
- Static export: components that read the store must provide a server snapshot so `next build` prerenders; run `npm --prefix frontend run build` as a phase gate.

## Deviations and Reconciliations

Changes to the approved Phase 1 contract and to shipped Phase 1 code. Each is deliberate.

| # | Phase 1 says | This spec requires | Reason |
|---|--------------|--------------------|--------|
| 1 | Min width 1024px; columns watchlist `minmax(300px,340px)`, chat 360px, trade 260px | Min width 1280px; watchlist 320px fixed, chat 320px, trade 224px | 01-UI-REVIEW.md fix 1: Chart/Heatmap collapsed to about 68px at 1024px. New values give every cell at least 206px at the minimum (arithmetic in Layout Contract). |
| 2 | Dot has `data-status`, `title` and `aria-label` on a generic `span` | `role="status"` plus a visually hidden text node; drop `aria-label`; keep `title` | WR-02 and 01-UI-REVIEW.md fix 3: `aria-label` on a role-less `span` is ignored by assistive tech. |
| 3 | Wordmark is a `span` | Wordmark is the page `h1` | No page-level heading existed; panel `h2`s had no parent. Style is unchanged. |
| 4 | Dot initial state `disconnected` (Phase 1 opened no stream) | Initial state `reconnecting` | Phase 3 opens the stream; CONNECTING is the true initial state. The Phase 1 Header test asserting a disconnected start is obsolete and must be replaced. |
| 5 | Under `prefers-reduced-motion`, "drop the transition and the background; show the change by the text color alone" | Drop the flash entirely; direction is carried by the daily change color and sparkline stroke, which are always colored | The price cell flash lasts about 50ms plus the fade, so a text-color change held only that long is imperceptible. Making it persistent would need a second per-ticker direction state for no real gain. |
| 6 | Selected-row styling and hover fill listed for watchlist rows | Phase 3 rows are non-interactive; hover, `tabIndex` and selection arrive with Phase 4 | Selection belongs to TRADE-01/02. Hover on a non-clickable row would suggest clickability. |
| 7 | `Panel` `section` has no accessible name | `aria-labelledby` pointing at the title `h2` | 01-UI-REVIEW.md Experience Design finding (unnamed panel landmarks). No visual change. |

## Decision Log (confirm in review)

No CONTEXT.md existed and no interactive channel was available. These were decided here with the recommended option. Items marked CONFIRM are the ones most worth the user's attention.

| ID | Decision | Rationale | Alternative |
|----|----------|-----------|-------------|
| D-01 CONFIRM | Raise the minimum width to 1280px, watchlist fixed 320, chat 320, trade 224 | Smallest change that gives every panel cell at least 206px and keeps the 312px watchlist row; keeps the 3-column center grid so Phase 4 and 5 layouts need no rework | Keep 1024px and collapse chat to a 40px rail below 1280 (chat is "open on load" in CHAT-01, so rejected) |
| D-02 | Failed watchlist load: `Watchlist unavailable. Reload the page to try again.` in `text-down`, `role="alert"`, no retry button | Mirrors the approved header failure pattern | Add a Retry button (extra state, not needed for a local app) |
| D-03 | Dot starts `reconnecting` (yellow); `role="status"` with hidden state text; stays red until a recreated stream opens | True browser state; no red flash on load; no flicker while retrying | Start `disconnected` (red flash on each load) |
| D-04 | Wordmark is the page `h1` | Fixes the missing page heading with no visual change | Add a visually hidden `h1` |
| D-05 | `color-scheme: dark` on `html` | Fixes light scrollbars and input chrome | none |
| D-06 | No column-head row in the watchlist | Saves 28px; `%` suffix plus `title` tooltips disambiguate the cells | Add a `Ticker / Price / Chg` head row |
| D-07 CONFIRM | Sparkline stroke is `muted` when the net change is exactly zero (`up` above, `down` below) | Consistent with the zero-is-`muted` rule; avoids a green line on flat data | Treat zero as `up` (simpler, one fewer branch) |
| D-08 | Add button disabled while the input is empty; focus returns to the add input after a successful remove; added row scrolled into view | Small usability fixes with one line each; no new state machine | Omit any of the three |
| D-09 | Header total never flashes or announces | The focal figure stays calm; avoids a 2 Hz live region | Flash the total (competes with row flashes) |
| D-10 | Reduced motion drops the flash entirely (Deviation #5) | Imperceptible otherwise | Persistent last-direction text color |
