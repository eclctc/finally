## Phase Goal

**As a** trader, **I want to** watch live prices stream into my watchlist, **so that** I can follow the market at a glance.

## Acceptance Criteria (this plan)

- [ ] One native `EventSource` to `/api/stream/prices` feeds a per-ticker store; frames merge and never replace; the stream stays out of top-level React state (LIVE-01)
- [ ] The store derives `connected` / `reconnecting` / `disconnected` from `open`, `error` and `readyState`, and recreates a CLOSED stream after 1 s (LIVE-02 logic; the dot UI is Plan 03-03)
- [ ] Rows come from `GET /api/watchlist` and show ticker, live price and daily change % against `open_price`, with `--` when there is no price (LIVE-03 core; states and full tests are Plan 03-04)

    `frontend/src/lib/priceStore.ts` is a plain TypeScript module singleton with no React import and a one-line docstring on every export. It holds:
    - private state: `entries` (Map ticker to PriceEntry), `histories` (Map ticker to readonly number[]), per-ticker listener Sets, a status listener Set, a version listener Set, `status` starting at "reconnecting" (D-03), and `version` starting at 0;
    - a private `applyTick(ticker, next, flash)` that stores a new immutable entry `{ price, openPrice: open_price, timestamp, flash }`, sets the history to a new array of the last `HISTORY_LIMIT` (300) prices including the new one, and notifies that ticker's listeners.

    Export functions:
    - `mergeFrame(frame)`: visits only the frame's keys. It skips an entry whose price is null (REST sends all price fields null together), and skips an entry whose timestamp equals the stored one. Compare timestamps only for inequality, never for order: the E2E fake frame uses 0. Flash is null when there is no stored entry, otherwise it compares raw prices: greater is "up", less is "down", equal is null. Never use the frame's `direction`. After the loop, if any ticker changed, increment `version` and notify version listeners once.
    - `seedPrices(frame)`: the same apply path, but only for tickers with no entry yet, with flash null. It must never overwrite a streamed entry, because the REST response can land after the first frame.
    - `clearTicker(ticker)`: deletes the entry and history, notifies that ticker and the version listeners.
    - `setStatus(next)`: notifies status listeners only when the value changes.
    - `getEntry`, `getHistory`, `getStatus`, `getVersion`. `getHistory` returns the exported frozen `EMPTY_HISTORY` constant for an unknown ticker. It must be the same reference on every call, because `useSyncExternalStore` compares snapshots with `Object.is`.
    - `subscribeTicker(ticker, listener)`, `subscribeStatus(listener)`, `subscribeVersion(listener)`: each returns an unsubscribe function.
    - `resetPriceStore()`: clears entries, histories and all listener sets, and restores "reconnecting" and version 0.

## Flagged Assumptions

- **Dot behavior after a CLOSED error (planner interpretation of UI-SPEC D-03 vs LIVE-02).** Status changes only on `open` and `error` events, and creating a stream never changes it. In the non-200 loop the UI-SPEC describes, every error is CLOSED, so the dot stays red until a recreated stream opens, with no flicker. If a recreated stream instead hits a network-level error, the dot shows `reconnecting`, because LIVE-02 reserves red for a CLOSED `EventSource`. Between creating a stream and its first event the dot keeps its last state.
- **Firefox and Safari** were not spiked (03-RESEARCH A2). If either fails a network error as CLOSED, the recreate path covers it.
- **REST seed records one history point.** A seeded price is a real cached tick with its own timestamp, so `seedPrices` shares the apply path and adds one point. The stream then dedupes by timestamp.
- **Prohibition recall breadcrumb (canon, not minted):** rendering SSE or REST strings as raw HTML is canon XSS, covered by `/gsd-secure-phase`. Plan 03-05's gate greps for a raw-HTML prop.
