## Phase Goal

**As a** trader, **I want to** chart, buy and sell tickers and see my portfolio update, **so that** I can manage my positions.

## Acceptance Criteria (this plan)

- [ ] Clicking a watchlist row selects that ticker and exposes it through `main-chart[data-ticker]` (TRADE-01, selection half; the chart itself is Plan 04-03)
- [ ] Selecting a ticker fills the trade bar's ticker field, without ever clobbering a ticker the user typed before the default selection (TRADE-02)
- [ ] The first watchlist ticker is selected by default (D-01), and removing the selected ticker falls back to the first remaining one

<objective>
Make watchlist rows selectable and wire one `selectedTicker` in `Dashboard` to the main chart wrapper and the trade bar. Then pin the trade-ticker prefill rule that keeps typed text safe from the default selection, and complete the row selection contract (keyboard, `aria-current`, selected style, default and fallback) together with the WR-04 color rule the row change cell needs.

Purpose: `watchlist.spec.ts` "clicking a watchlist row selects it in the main chart and trade bar" and every trade spec depend on this wiring, and the default-selection race is the main E2E risk named in research (Pitfall 2).
Output: `MainChart.tsx` (wrapper and caption), selectable `WatchlistRow`, `Watchlist` selection props and effect, `TradeBar` prefill, `signClass`, updated tests.
</objective>

- Detector hit: `chosen` on the ROADMAP word "custom" ("spike the Recharts 3 Treemap custom `content` renderer first"). That is a rendering choice inside the heatmap and changes no identity model (see Plan 04-04).
- Genuine seam, in this plan: the charted ticker changes from derived to chosen. It has a derived default (the first watchlist ticker, D-01) but is chosen by a row click. The trade ticker is a second value derived from the selection but overridable by typing.
- Primary noun: `selectedTicker` in `Dashboard`, set only by the user's row selection. The default is applied only when nothing valid is selected (null, or the selected ticker was removed).
- Decision: `promote`. The user's choice is primary and the derived default is demoted to a fallback inside `Watchlist`'s effect. The trade bar keeps its own `ticker` state that a selection change writes to one way. Orders always submit the field's visible value, and the default never overwrites typed text.
- Invariant tests: "a typed ticker survives the first (default) selection" (Task 2) and "removing the selected ticker falls back to the first remaining ticker" (Task 3).
</assumption_delta_decision>
