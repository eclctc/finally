## Color

Inherited unchanged. No new token, no raw hex, no pure black. Chart colors reference tokens as `var(--color-*)` or `color-mix()` over tokens.

| Role | Token | Phase 4 usage |
|------|-------|---------------|
| Dominant (60%) | `surface` `#0d1117` | Trade inputs, selected watchlist row fill, chart tooltip, heatmap tile gap stroke, chart plot wells |
| Secondary (30%) | `panel` `#1a1a2e` | Panel bodies, sticky positions head row; `line` for table row dividers, chart grid, tooltip border; `text`, `muted` |
| Accent (10%) | `accent` `#ecad0a` | Reserved list unchanged. Phase 4 activates item 3 only: the selected watchlist row's ticker. |
| Primary blue | `primary` `#209dd7` | Main chart line, P&L line, live-tail dot, tooltip active dot, keyboard focus ring, input focus border |
| Submit purple | `submit` `#753991` | Buy and Sell buttons (both purple, white label) |
| Up | `up` `#2fbf71` | Positive P&L and change text, profit tile tint |
| Down | `down` `#f0524f` | Negative P&L and change text, loss tile tint, `trade-error`, all error lines |
| Destructive | `down` | Error text only. Nothing in this phase deletes anything. |

Accent reserved for (exhaustive, unchanged): 1) the "Ally" half of the wordmark, 2) the `total-value` figure, 3) the selected watchlist row's ticker, 4) the yellow `reconnecting` dot state. The chart caption ticker and the trade ticker input do NOT use accent.

Semantic rules for this phase:
- Buy and Sell are never green or red.
- P&L and change cells pick their color from the value AFTER rounding to the displayed precision: `text-up` above zero, `text-down` below zero, `text-muted` when it displays as zero (`+$0.00`-class values show `$0.00` in `text-muted`). One shared helper serves positions, the chart caption and the watchlist change cell. This closes WR-04.
- Heatmap tile fill, per tile: `color-mix(in srgb, var(--color-up|--color-down) {m}%, var(--color-line))` with `m = 40 * min(|pnlFraction| / 0.05, 1)`. Zero P&L is exactly `line`. The 40% cap is deliberate: it keeps `text` labels at or above 4.5:1 on the strongest green (about 4.6:1) and about 5.7:1 on the strongest red. Do not saturate tiles further without switching the label color.
- Charts: one data line per chart in `primary`; reference lines are dashed `muted`; grid is horizontal only in `line`. Green and red are not used for the chart lines themselves.

Shared state placement (a layout-level contract, because several panels read the same data):

- `Dashboard` owns two pieces of shared state exposed to descendants (a context provider, or props; the implementation is the planner's choice):

Phase 5 calls the same `refresh()` and `refreshHistory()` after AI actions.
- Refresh rules: portfolio and history load on mount and re-fetch every 30 s (`setInterval(…, 30_000)`, cleared on unmount). After a successful trade: `setPortfolio(response.portfolio)` with no extra GET, then `refreshHistory()` (the backend records a snapshot immediately after each trade).
- `Header` is otherwise unchanged. Its `failed` alert shows only while `portfolio === null` after a failed first load (a failed background refresh with data in hand is silent).

### History window and the data the charts need (prerequisite, store change)

The Phase 3 store keeps a capped `price[]` per ticker with no times, so a time axis and a time tooltip cannot be drawn from it. Required store change (implementation by the planner, contract here):

- Keep, per ticker, a capped series of `{ t, price }` where `t` is the frame `timestamp` in epoch milliseconds (frame value is Unix seconds, multiply by 1000). Expose it through a new hook next to `useTickerHistory` (for example `useTickerSeries`). `useTickerHistory` and the sparkline keep working from the same series (map to prices) so the Phase 3 sparkline is unchanged visually.
- Raise `HISTORY_LIMIT` from 300 to 1,200 points (10 minutes at the 500 ms cadence). At 300 the main chart would silently cover only the last 2.5 minutes while captioned "Since page load".
- Caption honesty rule (Chart caption strip, right side): `Since page load` while `series.length < HISTORY_LIMIT`; `Last 10 min` once the series is full.
- `getEntry(ticker).openPrice` supplies the dashed `Open` reference line.

## Watchlist Selection Contract (TRADE-01, TRADE-02)

Applies to the existing `WatchlistRow` and `Watchlist` (Phase 3 anatomy unchanged).

- `li` becomes interactive: `tabIndex={0}`, `onClick` selects, `onKeyDown` selects on Enter or Space (only when `event.target === event.currentTarget`, so a key press on the `×` button never selects), `cursor-pointer`, `hover:bg-surface/60`, `focus-visible:outline-2 outline-primary -outline-offset-2`.
- `×` remove button: `onClick` calls `event.stopPropagation()` so removing a row does not select it (Phase 1 rule).
- Selected row: `bg-surface`, ticker `text-accent font-semibold`, `aria-current="true"` on the `li`. Exactly one row is selected at a time. `aria-current` is the only non-visual signal needed.
- Default selection: once the first `GET /api/watchlist` settles and nothing is selected, select the first ticker in list order. A fresh load therefore shows a populated chart and a prefilled trade ticker. (CONFIRM, D-01.)
- Selecting a ticker sets the Trade `Ticker` input to that ticker and updates `main-chart[data-ticker]` in the same render. Selection is one-way: typing a different ticker in the trade bar does NOT change the chart or the selection.
- Row membership and `watchlist-row-*` testid rules are unchanged (exactly 10 on a fresh DB; no other id in the panel may share the prefix).

## Trade Bar Contract (TRADE-02..05)

Panel `Trade` (`Panel title="Trade"`; it needs no testid, the controls carry theirs). Body: a single `div role="group" aria-label="Trade order"`, `flex flex-col gap-2 p-2`, `aria-busy` while a request is in flight. It is NOT a submitting `<form>`.

Top to bottom (inner width 206px):

1. Ticker input (`data-testid={testIds.tradeTicker}`): 28px, `bg-surface`, `border border-line`, `px-2`, Body, `placeholder:text-muted`, `focus-visible:outline-2 outline-primary`, border `border-primary` on focus. `aria-label="Ticker to trade"`, `autoComplete="off"`, `autoCapitalize="characters"`, `spellCheck={false}`, no `maxLength` (the backend error is the validation). Uppercases as typed. Controlled; its value is initialized and overwritten by watchlist selection.
2. Quantity input (`data-testid={testIds.tradeQuantity}`): same style, `type="text" inputMode="decimal"`, `aria-label="Quantity"`, placeholder `Quantity`, right-aligned `.figures`. No spinner, no wheel stepping.
3. Button row (`flex gap-2`): Buy (`data-testid={testIds.tradeBuy}`) and Sell (`data-testid={testIds.tradeSell}`), each `flex-1`, 28px high, `bg-submit`, white Body 600, `type="button"`, hover `brightness-110`, `focus-visible:outline-2 outline-primary`, disabled `opacity-50 cursor-not-allowed`. Buy and Sell look identical except for the label.
4. Estimate row (`flex items-baseline justify-between`): `Est. value` (Label, `text-muted`) and the figure (`figures`, Body, `text-text`, `whitespace-nowrap`). Value is `quantity x live price` for the typed ticker; `--` when no live price or no valid quantity. A rough guide, not a quote (the fill price is the backend price at execution).
5. Message slot (one at a time, absent from the DOM when empty): `trade-error` (`data-testid={testIds.tradeError}`, `role="alert"`, `text-down`, `break-words`) or the success line (`role="status"`, `text-muted`, `break-words`).

Behavior:

- Enabled rule for Buy and Sell: not in flight, ticker trimmed non-empty, `Number(quantity)` finite and greater than zero.
- Click: set in-flight, clear the message, `POST /api/portfolio/trade` with `{ ticker: trimmed, side, quantity: Number(quantity) }`, `Content-Type: application/json`.
- Success: `setPortfolio(response.portfolio)` (header cash and total, positions, heatmap update in the same render), then `refreshHistory()`; clear the quantity; show `Filled SIDE QTY TICKER @ PRICE`; move focus to the quantity input.
- Failure: show the backend `error` text (or `Request failed. Try again.` for a non-HTTP failure); keep both inputs; move focus to the quantity input.
- The ticker field accepts any symbol (held but unwatched tickers can be sold by typing them). The backend decides validity.
- Enter in an input does nothing.

## Heatmap Contract (PORT-02)

Panel `Heatmap` (wrapper testid `heatmap` unchanged). Body: when positions exist, a `relative h-full min-h-0 overflow-hidden` wrapper with `role="img"` and `aria-label="Portfolio heatmap, {N} positions, sized by market value, colored by profit or loss"`, containing `ResponsiveContainer width="100%" height="100%"` and a `Treemap`. The positions table is the accessible equivalent.

Treemap:

| Prop | Value |
|------|-------|
| `data` | one item per position: `{ name: ticker, value: liveMarketValue, pnlFraction, marketValue }` |
| `dataKey` / `nameKey` | `"value"` / `"name"` |
| `isAnimationActive` | `false` |
| `content` | a custom renderer (below). The default renderer draws `<path>`, which fails the `svg rect` selector. |

Custom tile renderer (`content`):

- The renderer is called for the root (`depth === 0`) as well as for each leaf. It MUST return an empty element for `depth === 0` so no full-size root rectangle is drawn.
- For `depth === 1` draw a `<g>` containing: `<title>` (native tooltip text from the Copywriting Contract), a `<rect x y width height>` with `fill` from the color mapping in "Color" and `stroke="var(--color-surface)" strokeWidth={1}`, and the labels.
- Labels: ticker `<text>` at `(x + 8, y + 20)`, Body 600, `fill: var(--color-text)`, always emitted (the spec asserts the ticker text is in the heatmap). P&L % `<text>` at `(x + 8, y + 36)`, Label size, `fill: var(--color-text)`, emitted only when `width >= 64 && height >= 40`. Text must be clipped to its tile (for example by wrapping the tile in a nested `<svg x y width height>` or a `clipPath`), so a small tile never paints a label over a neighbor.
- Fill never uses a raw hex; the `rect` fill value is a `color-mix(...)` string over `var(--color-*)` tokens, or the equivalent inline style.
- Tiles are not interactive (no click, no hover state beyond the native `<title>`).

Spike gate (Research flag, do before building the panel): in Recharts 3.10.1 confirm (1) the custom renderer receives the extra data fields (`pnlFraction`, `marketValue`) or find them by `name`, (2) the first `svg rect` inside `[data-testid="heatmap"]` is a visible tile rect and not a `clipPath` / `defs` rect (the spec reads `.first()` and requires `toBeVisible()`), (3) the root node is suppressed, (4) `toContainText("JPM")` passes against `<text>` content. If (2) fails, wrap the Treemap so the first rect in DOM order is a tile.

## P&L Chart Contract (PORT-03, PORT-04)

Panel `P&L` (wrapper testid `pnl-chart` unchanged). Body: `relative h-full min-h-0 overflow-hidden` wrapper, `ResponsiveContainer width="100%" height="100%"`, `LineChart`.

Series construction (pure functions, unit-tested; INT-01 revaluation coverage):

1. History: `snapshots.map(s => ({ t: Date.parse(s.recorded_at), value: s.total_value }))`, oldest first.
2. Downsample to about 300 points on the client: if `n > 300`, pick the indices `round(i * (n - 1) / 299)` for `i = 0..299` (always keeps the first and last snapshot; indices are distinct because the step is above 1). If `n <= 300`, use as is.
3. Live tail: append `{ t: now, value: liveTotalValue(portfolio, price) }` where `now = Date.now()` at the latest price tick or data refresh. Skip the tail while `portfolio === null`. The tail value is the same number as the header `total-value`.
4. Fewer than 2 points after step 3: show `Waiting for portfolio history.` instead of the chart.

Chart spec:

| Element | Spec |
|---------|------|
| Chart | `LineChart`, `margin={{ top: 8, right: 8, bottom: 0, left: 0 }}`, default `accessibilityLayer` kept |
| Grid | `CartesianGrid vertical={false} stroke="var(--color-line)"` |
| X axis | `XAxis dataKey="t" type="number" scale="time" domain={["dataMin", "dataMax"]} tickCount={4}`, tick format `HH:MM` when the span is under 24 hours, otherwise `Mon D`; tick style as the main chart |
| Y axis | `YAxis width={64} domain={["auto", "auto"]} tickCount={4} tickFormatter=formatPrice`; ticks keep two decimals because a flat portfolio can span only cents |
| Line | `Line dataKey="value" stroke="var(--color-primary)" strokeWidth={1.5} dot={false} isAnimationActive={false}` (renders the `path.recharts-curve` the spec asserts) |
| Baseline | `ReferenceLine y={10000} stroke="var(--color-muted)" strokeDasharray="4 4" ifOverflow="extendDomain"`, label `Start $10,000` (Label size, muted, `insideTopLeft`) |
| Live tail | `ReferenceDot x={tail.t} y={tail.value} r={3} fill="var(--color-primary)" stroke="var(--color-surface)"` marking the live point |
| Tooltip | custom content, `bg-surface border border-line p-2`, Label style: time `Mon D, HH:MM:SS` (`text-muted`), `Total value` + `formatCurrency` (`figures text-text`), `vs start` + `formatSignedCurrency(value - 10000)` colored by the rounded-value rule |

`STARTING_CASH = 10000` is one shared constant used for the baseline and the `vs start` row.

The chart re-renders on each price tick through the existing `usePriceVersion` subscription (the tail moves); no animation. History refetches every 30 s and after each trade.

## Deviations and Reconciliations

Changes to approved Phase 1 / Phase 3 contracts and to shipped code. Each is deliberate.

| # | Earlier contract / code says | This spec requires | Reason |
|---|------------------------------|--------------------|--------|
| 1 | Phase 3: watchlist rows are non-interactive | Rows are selectable (hover, `tabIndex=0`, Enter / Space, accent ticker, `aria-current`) | Phase 3 Deviation #6 deferred this to TRADE-01 / TRADE-02 |
| 2 | `usePortfolio` lives inside `Header` (IN-02) | One shared portfolio source (and history) provided at `Dashboard`; `Header` reads it | Trades must refresh the header total without a second fetch; Phase 5 reuses it |
| 3 | `usePortfolio` sets `failed` on any failed request, so `Header` shows the alert even when data is already loaded | `failed` surfaces only while no data has loaded; later failures are silent | Adding a 30 s poll would otherwise flash a permanent alert over valid numbers on one dropped request |
| 4 | Phase 1 / 3 store keeps `price[]` capped at 300 (`HISTORY_LIMIT`) with no times | Store keeps `{ t, price }` capped at 1,200 | A time axis, time tooltips and an honest "since page load" window need it. Sparkline stays visually unchanged. |
| 5 | Phase 1: dollar P&L is "`formatCurrency` with the sign from the formatter" (positive shows no sign) | New `formatSignedCurrency` with an explicit `+` | Color must not be the only direction signal |
| 6 | Phase 3: `WatchlistRow` change color comes from the unrounded value (WR-04) | Shared helper colors by the value after rounding; apply it to the watchlist change cell too | Closes open advisory WR-04 while adding the same logic to the new cells |
| 7 | Phase 1 chart rule: heatmap tile "fill `up` or `down` with intensity scaled by P&L %" | Mix capped at 40% over `line` | Keeps `text` labels at 4.5:1 or better on the strongest tile |
| 8 | Phase 1 `Panel`: only `testId` passthrough | No `Panel` change. `main-chart` and `data-ticker` live on an inner wrapper. | Avoids widening `Panel` for one data attribute |

Open Phase 3 advisories that touch this phase:
- WR-03 (`clearTicker` drops a held ticker's live price on watchlist remove): positions and heatmap now read live prices, so a removed-but-held ticker would fall back to the API price for at most one tick. Recommended fix in this phase: do not clear a ticker's entry when it is held. Not blocking.
- IN-04 (sparkline color compares the first and last point of a sliding window): with the larger cap the window is 1,200 points. Recommended: the sparkline slices to the last 300 points so its look does not change.
